## Portability and installation

- Dataset precedence: explicit argument, `DATASET_ROOT`, then YAML. `auto` selects
  `<repo>/data`, otherwise `../DatasetVer4_Public`. Relative YAML paths are anchored
  to the configuration directory. Three regression tests exercise relocation,
  working-directory independence and overrides.
- No machine-specific absolute paths remain in audited source/configuration/document
  text. Generated execution logs, virtual environments, retained historical worktrees
  and scratch files are outside that source audit.
- A copied handoff in a path containing spaces passed all 60 integrity checks from an
  unrelated working directory; its relocated registry loaded all seven model specs.
- Windows setup installed Python 3.11 CPU dependencies and the editable package;
  `pip check` passed. The final pins use torch 2.6.0, torchvision 0.21.0 and
  Ultralytics 8.4.161. An initial 8.3.100 candidate passed inference but lacked the
  `unwrap_model` training API; it was replaced before delivery.
- Windows Application Control blocked the standard-library venv executable generated
  by the managed Python distribution on this host. Creating the environment using uv
  resolved this host restriction; the setup launcher then completed. A normal Python
  installation with permission to create/run virtual environments is a prerequisite.
- During the initial incomplete-venv test, activation failure exposed a launcher bug
  that installed packages in the user interpreter. The process was stopped and those
  changes were reverted (SymPy restored to 1.14.0 and newly added packages removed).
  Launchers now check activation and invoke the venv executable explicitly on Windows.
- Bash launchers pass syntax checks. Linux/macOS execution was not tested on this
  Windows host. The pinned macOS target is Apple Silicon with ARM64 Python.
- Python 3.11/3.12, Internet during setup, and the checkpoint handoff are required.
  Dataset-dependent tests and Gallery/parity require the external dataset. A Git clone
  alone lacks the three git-ignored checkpoints. Direct dependencies are pinned;
  transitive versions are recorded as execution evidence, not a universal wheel lock.
